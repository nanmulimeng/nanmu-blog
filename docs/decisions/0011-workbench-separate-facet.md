# ADR-0011: 公开站「无后台」约束的分面调整——作者工作台为独立分面

- 状态:已接受(2026-10-21 工作台设计评审通过;2026-10-25 补记入库——批 1 实施时未同步落 ADR,本文补齐,作为批 2 前置任务 1.0 的一部分)
- 日期:2026-10-21(评审)/ 2026-10-25(入库)
- 关联:ADR-0002 / ADR-0010 / [工作台 DESIGN](../design/2026-10-20-writing-workbench/DESIGN.md) / [实施 PLAN](../superpowers/plans/2026-10-21-writing-workbench-implementation.md)
- 取代范围:无——不修改 ADR-0002/0010 任何条款,只澄清其适用边界

## 背景

写作工作台(编辑器/预览/发布)若混入公开站,会引入会话、凭据与动态服务面,与 ADR-0002「无后台无数据库」「git 即 CMS」冲突。工作台设计评审(2026-10-21 审计收口)已定案分面架构,本 ADR 将该决策入库。

## 决策

1. **公开静态站保持不变**:仍无后台、无数据库、无会话;客户端 JS 白名单以 ADR-0010 为准,不因工作台新增任何入口。
2. **作者工作台是独立分面**:`write.nanmu.xyz` 独立服务(自有进程/口令认证/服务端会话/文件草稿存储),**不混入公开站构建产物**;公开站构建仍由既有 git push → hook 链路承担,工作台发布=操作 Git 双远端,不直写公开站。
3. **预览为静态校对分面**:真实 Astro 构建产物 + CSP sandbox(无 allow-scripts)+ 资源短期 token,详见 DESIGN §4.3。
4. **凭据边界**:工作台口令只进服务器 env 文件,不进仓库/脚本/日志(与项目既定凭据纪律一致)。

## 后果

- 公开站的攻击面与运维形态零变化;工作台故障不影响公开站在线(呼应「任何一层挂掉博客都在线」)。
- 工作台自带认证/会话/存储复杂度,由其自身 DESIGN 契约与测试约束,不由公开站承担。

## 被否决的替代方案

1. 工作台并入公开站(同域路径)——引入会话面,违背 ADR-0002,否决。
2. 用第三方 CMS 托管写作流——供应商依赖与「git 即 CMS」冲突,否决。
