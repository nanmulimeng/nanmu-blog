# ADR-0001: 博客与 AI 引擎分离,渐进整合

- 状态:已接受;发布细节由ADR-0009补充(commit必须push并取得线上回执)
- 日期:2026-10-02
- 关联:spec §1.2 / §3

> 2026-10-04有效口径:当前边界:engine不负责正式部署构建,但提交前必须调用现有site verify验证产物;发布由独立hook执行。

## 背景

三前项目结论:nanmuli-blog 因一开始把博客/采集/AI/后台全部耦合设计,12.5 周烂尾;topic-digest 极简独立,720/720 全绿。本项目需求是"博客简单版本 + AI 连接层是重心"。

## 决策

两件独立工件:`site/`(Astro 静态站)与 `engine/`(Python 独立进程、独立 SQLite),通过 **markdown 文件 + git** 单向衔接(engine 只产出 digest markdown 并 commit,不碰构建)。按里程碑渐进整合:M0 博客先上线 → M1 引擎 → M2 RAG,每个里程碑独立可发布。

## 理由

- AI 挂了博客照常在线(铁律 2/3)的根本保证是进程与数据的物理分离
- "每个里程碑独立可发布"是 nanmuli-blog 头号教训(范围失控)的解药
- 文件 + git 衔接 = 天然溯源、回滚、离线可复现

## 后果(代价)

- engine → 博客的发布延迟以分钟计(走 git + 构建链),对每日一期日报无影响
- 两套部署单元的运维面(timer + hook)

## 被否决的替代方案

1. 一体化(博客后台内嵌 AI 功能)——nanmuli-blog 老路,范围失控,否决
2. 纯静态博客无 AI——放弃项目重心,否决
3. AI 产物直接写文件系统不走 git——失去溯源与回滚,否决
