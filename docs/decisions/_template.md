# ADR 模板

> 复制本文件为 `NNNN-<短横线标题>.md`(编号接续)。一个ADR记录一个值得长期追踪的架构决策;决定改变用新ADR并注明取代范围,事实勘误可追加说明,不悄悄改写历史理由。

```markdown
# ADR-NNNN: <决策标题>

- 状态:已接受 | 提议 | 被 ADR-XXXX 取代
- 日期:YYYY-MM-DD
- 关联:spec §X / ADR-YYYY(使用相对链接)
- 取代范围:无,或列出旧ADR中不再适用的条目
- 当前实施入口:对应plan/操作手册的链接

## 背景
(迫使做决策的约束与事实;引用环境文档而非复述)

## 决策
(做了什么;精确到可执行的程度)

## 理由
(为什么是这个;证据/调研结论要给来源)

## 后果(代价)
(诚实地写代价与新增负担——没有代价的决策不存在)

## 被否决的替代方案
1. 方案 A——否决理由
2. 方案 B——否决理由
```

## 写作要点

- 终态原则:交付文档不引用草稿/评审轮次;被否决方案只留结论与理由
- "后果"必须包含代价——这是防止未来读者盲目崇拜旧决策的部分
- 现有示例:0001-0009(设计基线与实施前契约修订)
