# ADR-0011: 作者工作台为独立分面——公开站「无后台」约束不变

- 状态:已接受(2026-10-21 批 1 实施首步落地)
- 日期:2026-10-21
- 关联:ADR-0002 / ADR-0007 / ADR-0010 / [工作台设计 DESIGN.md](../design/2026-10-20-writing-workbench/DESIGN.md) / [实施计划 PLAN](../superpowers/plans/2026-10-21-writing-workbench-implementation.md)
- 取代范围:无条目被取代;对 spec 与 ADR-0002 的「无后台无数据库、git 即 CMS」表述做**分面澄清**——公开站约束不变,作者侧新增独立分面

## 背景

批次 C 用户实测反馈:文章管理与撤稿只能手工 push、链路重、易出错(《你好,nanmu-blog》撤下全链路手工完成)。工作台设计(2026-10-20)经定点/契约纠正/收口/勘误/首版收敛多轮评审于 2026-10-21 收口通过。spec 与 ADR-0002 确立「无后台无数据库、git 即 CMS」;引入工作台若不加澄清,与这些表述直接冲突,须先定分面边界再开工(设计 §8 预留本 ADR 为实施第 1 步)。

## 决策

按**分面**拆分,两侧各自成立:

- **公开站(读者侧)保持不变**:仍无后台、无数据库、无会话,静态文件+git 即 CMS;客户端 JS 白名单(ADR-0010)不变;读者侧与工作台零耦合。
- **作者工作台为独立分面**:独立服务(systemd `nanmu-workbench.service`,write.nanmu.xyz,Caddy 反代子域,单用户口令+会话);草稿与操作记录存工作台私有数据目录(不在公开仓库内);工作台页面不混入公开站构建产物;发布/撤下的唯一出口=git commit+push 既有 deploy bare 与 post-receive hook(ADR-0007 链路),与作者手工操作完全同权同路,不改 hook。
- 边界:工作台不引入数据库服务(会话=内存表,草稿=文件);不做读者侧任何功能;不新增第三方网络依赖;不改 engine/timer/付费配置。

## 理由

- 写作与撤稿的操作风险在作者侧;公开站静态架构(性能/攻击面/备份简单)是已验收的既定收益——分面拆分两头都不牺牲。
- 「无后台」的本意是「公开站不为读者引入动态面与数据库」,不是「作者不得有工具」;以 ADR 澄清语义比改写 spec 全文代价小、误伤少。

## 后果

- 「无后台无数据库」表述按分面理解:公开站无后台;作者工具有独立入口与凭据(口令与会话只在 write 子域)。
- 新增一个服务器服务与子域的运维面(systemd/env/Caddy 反代段,批 4 部署按部署手册授权)。
- spec 三处「无后台」表述加注指向本文(2026-10-21 定点同步,不做全仓整理)。

## 被否决的替代方案

1. 给公开站加管理后台(动态服务+数据库)——否决:破坏静态保证,攻击面与运维复杂度大增,ADR-0002 已否决同路。
2. 继续纯手工 push——否决:批次 C 实证撤稿链路过重、易错。
3. 工作台做成静态站生成器插件——否决:认证/会话/操作恢复仍需服务进程,伪装成插件不减少面,反而混入公开构建。
