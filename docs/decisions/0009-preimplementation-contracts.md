# ADR-0009: 实施前收敛成本、发布与验收契约

- 状态:已接受
- 日期:2026-10-02
- 关联:spec §5/§7/§9;补充 ADR-0003/0004,部分取代 ADR-0005/0007

> 2026-10-04有效口径:现行细节入口:[管线恢复](../engine/pipeline.md)、[成本治理](../engine/budget.md)、[部署操作](../ops/deploy.md)。本ADR保留长期决策,不继续累积局部实施步骤。

## 背景

文档审查发现:调用次数上限不能保证月金额上限;本地 commit 不触发远端 post-receive;非阻塞锁会漏掉后到的发布请求;下一阶段计划被误列为当前阶段的完成条件。上游源码还证实 `cluster` 已使用,不能把 `clustered` 当作无效候选。

证据与审查边界见 [文档审查记录](../reviews/2026-10-02-documentation-audit.md)。这些是既有目标的实现约束,不增加 M0 产品功能。

## 决策

1. **里程碑独立验收**:当前阶段通过自己的验收即可完成;下一阶段计划与用户评审是进入下一阶段的条件。文档会话不要求运行不存在的应用测试。
2. **金额与次数分别限制**:保留三级调用次数窗口,另加月度 ¥50、单期 ¥1 的调用前额度检查与保守预占。¥40 是预警线。结果未知的调用继续占用额度;重试另占额度。缺少计价或预算配置时禁止付费调用。M2 所有付费问答/embedding 同样纳入月预算。
3. **调用尝试单独留痕**:增加 `receipt_attempt` 表,逐次记录时间、预占、实际用量与未知结果。逻辑回执复用已收响应;本地幂等键不宣称能保证供应商端绝不重复计费。prompt、输入内容和模型配置变化必须进入请求身份。
4. **发布有明确回执**:engine 在专用工作副本提交并 push 到 bare repo;push 成功只代表接收。站点暴露构建 SHA 标记,确认相应日报可见且线上版本包含该提交后才能记 `published`。发布失败复用已有 markdown/回执,不重新付费生成。
5. **后台构建有界等待**:M0 hook 断开标准输入输出后启动后台任务;构建锁有界等待,取得锁后读取最新 main。超时/失败必须记日志并可手动重跑,不能把丢弃请求称作串行队列。只切换经 build+smoke 成功的完整 release,失败目录不能当缓存复用。
6. **外部事实与历史分层**:上游本地源码、历史验收、当次线上实测分别标注。服务器状态不由本地代码推断;外部选型的版本、价格、内存与延迟在实施阶段复核。

## 后果(代价)

- M1 多一张调用尝试表和额度预占逻辑,必须测试崩溃、未知结果与跨窗口重试。
- M0 后台任务仍不是持久化任务队列;服务器重启会丢失等待任务,巡检发现线上 SHA 落后后按 runbook 重跑。
- M1 多写者 Git 冲突、发布确认超时、人工回滚后的日报状态重核需要在其计划内明确;M0 不提前实现引擎。
- ¥50 是在已核实计价与受控请求范围下的应用预算;供应商价格变更、账户外调用仍需账单核对。

## 被否决的替代方案

1. 保留次数限制并继续声称金额硬上限——token 长度、输出上限与单价都会改变成本。
2. 部署忙时直接跳过后到请求——远端 main 可能已更新,原样重推会显示 up-to-date 而不触发 hook。
3. 为解决发布等待引入常驻队列服务——超出当前规模,有界锁等待与显式重跑足够。
