### 反例 ③:多次撤回及修正后恢复的版本事实不完整(再撤回被误判 relisted——用户内存 SQLite 实测;修正后恢复的预期身份无持久化来源;查不到匹配提交≠"未真正 commit";ls-remote 不证明历史 SHA 被接收)

- **修订后状态**:**内容操作记录协议(digest_issue.ops_json,受约束 JSON 数组 append-only,不新增表)**:①每次改变公开内容的操作(撤回/重上/纠错)**开始即 append 未完成项** `{seq, op, target_sha256, stages:{commit?, pushed?, confirmed_utc?}}`(撤回 target=固定 ABSENT;**修正后恢复=修正稿落盘时即算 sha256 入库——目标版本出网前持久化**);②各阶段补记;线上确认→置 confirmed_utc,在线类操作同事务 UPDATE content_sha256=该 target(**content_sha256 语义升级="当前已确认线上版本"**,历史经 ops_json 追溯);③**当前可见状态=最新 confirmed 项的 op 类型**(withdraw→处于撤回;relist/relist_corrected→已重上;correct→在线纠错版;无→按 digest_issue.status)——**withdrawn/relisted 专用列降为"最近一次该类操作确认事实",不参与判定**;**再撤回=append 第二个 withdraw 项,确认后最新 confirmed=withdraw→回到撤回态**(修复实测反例);④**中断恢复**:存在未完成项→按其 op/target 先查远端与线上再补记;⑤**查找失败=证据不足→转人工**(E8 类;引擎不区分本地未提交/对象缺失/远端已接收/现场异常,**不把未知当重新生成许可**;人工确认未提交后可选重组装零新增);⑥**远端接收判定=fetch 后 SHA 是 origin/main 祖先**(merge-base --is-ancestor;ls-remote 只列 ref 尖端)——W3 窗口与 draft→submitted 推进均改此判据。
- **账本**:全部内容操作零模型调用;纠错重写摘要=新身份新费用归期(既有);四窗口与未完成项恢复均零新增。
- **文件**:units/publish-withdraw.md 规则 1(身份语义)/2(推进表+证据链基准)/3(W3 可达性+查找失败转人工)/5(**协议+撤回序列+再撤回**)/6(纠错 append correct 项)/7(重上两条+状态判定);spec §5.3 digest_issue(ops_json 列+四列注释改)。

### 反例 ④:restore-backup 自身中断窗口(恢复整库→置 pay_paused 两步之间崩溃→旧库已生效标志未写→下次 timer 放行付费)

- **修订后状态**:**先持久化、后切换**——restore-backup 全程持单实例互斥,五步序列:①备份文件恢复到**待启用副本**(不动活动库)→②副本上置 pay_paused=1→③**读回校验**(key 存在且=1,失败中止不切换)→④**原子切换**(副本 rename 为活动库)→⑤输出核对清单。各步后崩溃:①-③=活动库未动可重试;④后=新库已含标志。**不变量:活动库完成切换 ⇔ 其内 pay_paused=1 已先持久化**(不存在"已启用旧库但付费未暂停"中间态;**"先恢复后置位"顺序明令禁止**)。**闸门读法(单元二规则 1 同步):仅显式 0 放行;=1 或键缺失(违规裸恢复/库损坏异常态)均拒绝新增**——合法库建库/初始化即写默认 0,键缺失不可能为正常新库;status 检测活动库无键即提示核对。

## 决策记录(本轮新增)

| 决策 | 理由 |
|------|------|
| tokenizer 计数而非继续调字符系数 | 官方换算明示"大致比例"且随模型分词变化,任何系数都推不出上界;可验证计数=唯一能支撑"实付≤预占"承诺的方案;选型核对列 M1 第一步而非留空 |
| 对账超计数=停新增(删容忍个位) | 与"供应商实付>预占"同性质=上界失效;留容忍个位等于承认上界不闭合作者承诺 |
| 名额按类别拆(三条件) | budget.md L20 原意=普通 max_attempts+unknown 条件性一次;只比总数把两类混成一个池,反例 2<3 即穿 |
| ops_json 列而非新表/平台 | 用户要求不扩表;digest_issue 单列受约束 JSON 满足"目标版本+阶段"最小约定;append-only 与既有 manifest_json 同风格 |
| 状态判定=最新 confirmed op | 列组合(withdrawn/relisted)是"历史事实集合",天然表达不了"最近一次已确认操作";专用列降级为查询投影 |
| 先置位后切换+键缺失即拒 | 两步顺序倒过来才有窗口;缺失即拒使"裸恢复"这一违规路径也落在安全侧(默认拒绝新增付费) |
