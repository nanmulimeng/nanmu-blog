# 2026-10-26 MVP 冲刺经验总结(2026-10-21~26 六会话轮)

> 范围:nanmu-blog「博客+爬虫 MVP」双线推进全程(批 1-4 工作台、C4-C6 发布轮、五域检验、M1 校准与首期)。原则:只记可复用的,session 正文已有的细节不重复。

## 一、方法论层的收获

1. **验收必须含存在性断言,否则"跳过即恒真"**:发布 e2e 的点击断言写成 `if (元素存在) {点击}` 后断言 url 不变——元素不存在时断言恒过,四个 PASS 全是假阳性。修法:先 `assert count>=1` 再操作。此后所有验收断言先验存在。
2. **e2e 的价值=抓集成层缺陷**:单测 71/71 全绿的同时,e2e 抓出 4 个真缺陷(预览触发 API 整个缺失/预览 URL 返回站点根/CSS 相对分片缺 token/撤下不轮询确认)——都在"组件各自正确、组合语义错"的缝里。集成断言不可被单测替代。
3. **真实数据是最后 20% 的考试**:engine 330 测试全绿,首期真实跑连出四个根因(源配置漏配/部署 env 漂移/上游判重现实/门槛把关)——其中两个是"文档定案后部署侧没跟上"的配置漂移。**设计文档改了,部署清单必须跟着改**(env.example 与服务器 env 的差异要例行 diff)。
4. **多角度分域检验**:五域(前端/后端/数据库/工作台/仓库一致)模式在大型里程碑前值得固定;每域独立 fixture+独立判定,汇总时按域报告。
5. **卡点协议的实战节奏**:同一问题第 3 轮出现新根因时停下收口(首期四轮调查),把"根因假设/已试/已排除/建议"落成 session 再请决策——避免在别人的系统(td)里散弹枪。

## 二、工程踩坑集(全部实测,防复发)

| 坑 | 现象 | 解 |
|---|---|---|
| light-my-request 的 set-cookie | 有时返回字符串,`[0]` 取到首字符 'w' → 一切请求 401 | `(Array.isArray(sc)?sc[0]:sc).split(';')[0]`;**401 谜团先查 cookie 取法** |
| 逐字复制长随机串给人 | 公钥第 52 位 r 发成 q,用户两次贴"错"都对的——错在源头 | 发送前后与工具输出逐字符 diff;给用户可校验的指纹(SHA256 前缀) |
| `git status --short \| head -N` | 截断吞掉 untracked 行,favicon.svg 因此漏提交线上 404 | 列文件清单不做 head 截断;提交后对照预期文件数 |
| markdown 吃哨兵 | `__x__` 被解析为粗体,验收找不到哨兵 | 哨兵用连字符串 `sentinel-real-xxx` |
| 子进程无输入流挂起 | `git hash-object --stdin` 等 stdin 永远阻塞,测试全挂无输出 | 外部命令统一 timeout;诊断用"无缓冲实时日志重定向"(管道 tail/head 会缓冲到 EOF) |
| ssh 嵌套 pkill | `pkill -f sample.sh` 匹配到自己所在的远端 shell,自杀 255 | 模式用 `[s]ample` 字符类,或独立 runner 脚本(命令行不含模式串) |
| ssh 内嵌 heredoc | 引号/转义经三层解析必炸 | 本地写文件 → scp → 远端执行 |
| Windows flock 不存在 | 构建锁跨平台 | 注入式:`wrapLock(cmd, lockFile)`,无锁直跑(本地)/`flock -w 900` 包裹(生产) |
| cgroup v1/v2 | memory.current 不存在 → 采样恒 0(假零!) | 双路径回退 usage_in_bytes;**检查脚本输出 0 先怀疑脚本** |
| journalctl 时间过滤 | `--since "09:14"` 按 CST,日志时间戳混合 UTC/CST,漏行 | 用 `-n N` 按行取;查库时间列时显式带时区换算 |
| SQLite CHECK 组合约束 | `status='draft'` 改不进去(非 failed 必须有 markdown_path) | 失败期复位=删行(让 run 全新处理),回执复用零重复付费 |
| Git Bash heredoc + python 双层转义 | `\\n` 层级错,patch 匹配失败 | 复杂 patch 用 Write 工具写脚本文件再执行,不走 shell 转义层 |
