# 全站前端设计冲刺任务书

> 2026-10-08 用户最新要求：设计模型仅剩几天可用，集中完成所有前端页面、动画规划与 3D 资产；现有效果偏单调，需要更丰富、更惊艳的表现。本文是交给设计执行 AI 的任务书，**不是已完成设计或生产实施验收**。
> 推进方式更新：连续完成一套全站可浏览原型与资产包，中途报告进度，不逐页停下等待审美审批。既有 R2 修正同批处理，不再作为其他页面设计的总开关。最终集中评审一次。
> **创意优先级补充**：用户进一步要求充分发挥设计模型的想象力，允许科技感、鲜明色彩与更大胆的空间表现。先读 [参考研究与创作挑战](CREATIVE-REFERENCES.md)。R2 小院是已有资产起点，不是必须保留的最终美术风格；下文的小院、纸面、印章均可换成统一的新表达。

## 1. 创作目标与边界

从 [R2 设计](README.md) 的「营造」出发，探索个人写作与数字空间的完整视觉语言。可以保留小院，也可以重新解释为现代书斋、知识装置或其他原创空间。允许重做构图、材料、色彩、字体与动态表现；纸墨、朱砂、传统屋面都不是必选项。先以两张不同气质的首屏关键画面和短动态试验比较，再自主选出最有辨识度的一套发展全站，不制作两套完整网站等待用户逐项决策。

本轮交付重点是页面原型、可运行的动画、可编辑 3D 源资产和可接续的组件规范。沿用本目录，保护现有 R1/R2 产物；不得把未来效果描述为已经验证。现有站点路由依据 `site/src/pages/`，功能依据 [spec](../../superpowers/specs/2026-10-02-nanmu-blog-design.md)。

- 设计原型可使用为展示动效和 3D 所必需的浏览器脚本；依赖在独立原型环境中固定版本，不修改正式 site 的依赖或用远端未固定 CDN 作为最终交付。
- 生产仍以 Astro 静态内容为基础；局部交互的架构参考 [Astro Islands](https://docs.astro.build/en/concepts/islands/)。这不是升级 Astro 或迁移 SPA 的要求。
- 正式客户端 JS 约束的修订建议应覆盖主题、动效、局部 3D 的实际需要，不再预先限死为“只有主题切换一个例外”。正式 spec/ADR/门禁修改归后续实施，本任务书不静默覆盖现有规则。
- M1 校准、付费、服务器、发布保持原授权边界。M2 仅提前保存交互与视觉方案，不实现索引、问答 API、认证或真实模型调用。
- 不新增评论、用户中心、后台、标签管理、热度仪表盘或 M3 功能来填充页面。标签继续作为既有元信息展示。

## 2. 全站页面清单：全部制作可查看原型

现有公开页面按真实路由设计；新增体验优先是当前页面上的组件，不顺手新增生产路由。长内容、空状态及未来内容使用清楚标注的夹具。

| 页面/体验 | 设计任务 | 必须呈现的状态与交互 |
|---|---|---|
| 首页 `/` | 作者与真实文章首屏可见；3D 小院是品牌主视觉；文章与日报入口层级清楚 | 当前 1 篇文章/0 日报；有多篇文章和日报的夹具；两种主题；移动端内容与场景关系；场景加载/失败的静态替代 |
| 文章列表 `/posts/` 及分页 | 完整目录视觉、日期/标签层级、跨页节奏；多内容时仍成立 | 当前少量内容、多页夹具、长标题、末页；上一篇/下一页的触控及键盘反馈；不为设计新增标签筛选后端 |
| 文章详情 `/posts/{id}/` | 长文阅读、标题与元信息、章节、目录（如采用）、阅读进度、图片/代码/引用/表格 | 中文长文、中英混排、长 URL、宽代码与表格、图片图注、无图文章；图像展开与关闭若采用则可操作；正文不因动效隐藏 |
| 日报列表 `/digest/` 及分页 | AI 与手写内容的视觉区分、日期、模型、条目数、成本与未决提示 | 空列表、少量及多页夹具、长模型名、含未决/无未决；始终有明确 AI 生成文字，不能只靠「机」印章 |
| 日报详情 `/digest/{id}/` | 直接对齐引擎 Markdown 输出；设计图签与正文的关系 | 头条/精选/值得一瞥，空板块省略，来源/展示分/人工纳入、长摘要、成本三处一致；少条与满量夹具 |
| 关于 `/about/` | 独立构图与作者表达，项目经历可以是一段故事；小院细节可作第二视角 | 使用已知个人信息，缺失资料留明确待填位；手写/AI 栏目定位、RSS 入口；不得编造职业、城市、成就或外链 |
| 404 | 有辨识度的迷路/院门意象与短动画；回首页和目录路径清晰 | 不存在页面与撤回内容使用通用不存在语义，不泄露撤回文章；真实 HTTP 404 仍归正式站点契约 |
| 订阅入口（现有页内区域或弹层） | 文章 RSS 与日报 RSS 的双入口，简短订阅引导，可选复制反馈 | `/rss.xml` 与 `/digest.xml` 保留；复制成功/失败、无 JS 的可选中文本链接；不是新增邮件订阅服务 |
| 全局导航与页脚 | 桌面/移动菜单、当前位置、三态主题、键盘焦点、页面间视觉连续性 | 菜单开关/返回/关闭、系统主题变化、存储不可用；无脚本仍可导航；页脚不堆工程说明 |
| M2 私人检索/问答预案（仅独立原型） | 与博客同一品牌，但明确属于受保护的自用工具；设计入口、查询、来源阅读 | 未认证说明、初始输入、检索中、来源结果、有依据答案、证据不足、仅片段降级、服务不可用、预算停用；纯夹具切换，不接 API，不把公开博客入口做成已上线功能 |

“全部页面”指这张清单及其共用状态，不是为每个 URL 复制页面。桌面、手机、浅色、深色共用组件与 token；设计索引中逐项链接并标清已完成、局部缺失、仅概念。M2 布局/API/授权细节仍以未来 M2 评审为准。

## 3. 3D 主视觉：交付真实可运行资产

R2 的 SVG 小院保留为轻量版本与降级图。本轮另外制作一个**真实三维场景的可交互原型**，让用户比较空间增强的实际价值，不再仅以二维线稿冒充模型交付。生产是否采用该版本取决于整套效果与实测成本。

- 原创且可编辑的空间主视觉：可以是小院，也可以是现代建筑、书页装置、悬置档案或设计 AI 提出的更强概念。材质、色彩、几何语言自主选择；蓝紫、光谱、金属、玻璃都可探索，成败看整套构图与个人辨识度，不按颜色预先否决。
- 至少包含固定主镜头、有限角度交互、恢复默认视角，以及光照/材质与浅深主题的转换。可用小幅指针响应或用户拖拽；触控明确划分场景操作与页面滚动。
- 做一次有节奏的入场，例如图纸线条出现、建筑体量落位、材质建立、灯光点亮；文章入口从开始就可用，不做挡住内容的片头加载页。
- 房间/对象聚焦有可见反馈；真实链接保留等价 HTML 入口。规划中区域可以展示说明，但不能伪装成可用检索入口。
- 环境动效可有树影、光斑、极轻的纸面或窗光变化，用空间层次形成惊艳感。持续效果提供停止方式，页面隐藏或场景离屏时暂停；减少动态偏好下呈静态完成态。
- 交付可编辑源文件或完整确定性程序化建模脚本，不接受只有渲染截图或临时目录中的生成器。附导出资产（若采用文件模型，优先通用格式）、纹理/材质、镜头/灯光参数、运行入口、静态 poster 与移动端简化版本。
- 提供资源清单：模型/贴图/脚本大小、几何量、纹理尺寸、依赖版本与来源、测试设备与观察结果；缺测项明确标出，不把设计预算写成实测值。
- 不采购付费模型，不使用来源不明的素材；需要用户素材时使用显式占位继续其他工作。

## 4. 全站动效编排：从单点 hover 变成完整体验

以下是应制作并演示的动效方向，设计 AI 可以改进表现方式。每项记录触发、起止状态、时长/缓动、重复条件、键盘/触控行为与减少动态替代，不只留一句“以后加动画”。

| 层次 | 建议表现 | 完成证据 |
|---|---|---|
| 首页主场景 | 建筑入场、镜头轻缓落位、日夜光照过渡、房间响应 | 实时可操作原型 + 一段完整录屏；静态 poster 与原型同构 |
| 页面之间 | 列表标题到详情标题的视觉衔接、纸面/版心展开、返回时内容位置连续 | 首页→列表→详情→返回的一条可点击链；直接打开深链接同样可读 |
| 内容进入视口 | 章节引线、插画、信息卡轻量错峰出现；避免每段正文都动 | 长页面滚动演示，未触发观察器/无 JS 时内容仍显示 |
| 列表与导航 | 行式目录的强调线、印章或书签反馈、移动菜单分层展开 | 鼠标、Tab/Enter/Escape、触控分别有等价状态 |
| 长文阅读 | 细阅读进度、章节定位反馈、图片展开、代码复制反馈（选择有价值者） | 正文长样张可实操；滚动和键盘阅读保持原生可控 |
| 日报阅读 | 板块识别、来源链接提示、费用说明展开；避免金融数字滚动装饰 | 与真实 Markdown 结构一致的夹具；交互不改变金额或标注含义 |
| 关于与 404 | 与小院一致的第二视角、院门/小路/书桌等局部场景，复用源资产 | 两页独立构图，不能只换标题复用首页；不要求每页一个 WebGL 场景 |
| 全局主题 | 背景、纸面、正文和场景光照协调转换；模式选择反馈清楚 | 系统/浅/深，跨页一致、首次绘制、失败回退的演示与实测边界 |

不要把“多动效”实现成所有东西持续漂浮。允许主视觉富有戏剧性，但读文章时保持稳定；不接管滚轮、不把自定义光标当唯一指针、不以声音或强闪烁制造表现。给低能力设备的是同风格的简化体验，不是空白。

## 5. 设计系统与内容契约

建立足够支撑全站的共用 token/组件：浅深主题的背景层、文字层、强调文字/装饰色、字体角色、间距、网格、描边、阴影、圆角与运动参数。允许调整当前配色，但必须给出完整双主题页面，不只展示主视觉。

- 首次打开时内容与导航可用；模型/字体失败不破坏阅读。场景加载占位与最终尺寸一致，减少布局跳动。
- 元信息仍读取已有 frontmatter。R2 日报样张应同批改为现有 Markdown 结构；保留三板块、展示分、来源、人工纳入与成本标注。
- `cost_pending=false` 只是不追加未决提示，不自动标“已核清”（旧文件有缺省兼容）；true 沿用既定未决预占文案。删除“选自当日采集”的不成立承诺。
- 日报已发布数量不能永久充当功能建设状态。空列表使用“暂无已发布日报”等中性文本，不从 0 期推导服务故障或未建成。
- 字体固定分片可继续，但锁定源文件身份/范围/生成依赖，避免在线新范围与旧编号分片混用。生产候选仅保留实际字体需求；记录首载成本、版权与回退。这个修正不能阻塞其余页面设计。
- 不继承旧博客 Vue/API/后台等实现。当前客户端 JS 禁令与新交互需求之间的正式调整集中写一份建议，不让每个按钮成为一次审批。

## 6. 连续执行顺序与有限时间分配

不承诺实际工期，按剩余模型可用时间优先保存最不可替代的设计产物。建议分配：约 45% 全站页面与状态、30% 主场景与动态体验、15% 统一与可访问性检查、10% 资产整理及接手说明；可按完成情况调整。

1. 先做两张首屏关键画面与短动态试验，快速选定美术语言（参考研究里的创作挑战）；随即补齐全部公开页面的可点击骨架和视觉完成稿。R2 组件可复用也可调整，建立全站入口索引；已知两类修正同批做。
2. 制作 3D 源场景与可交互版本，完成动效演示页并接入主页面体验链；每做完一个独立场景就保存源文件，不能把关键产物只留在内存或临时目录。
3. 补齐双主题、移动端、空/长内容、失败和减少动态状态；M2 私人界面采用独立夹具页面提前留稿，不与公开页面的功能状态混淆。
4. 合并全站样式与交互，真实浏览器检查，打包可移交资产。过程中报告进度并继续独立工作；不逐页停下等确认。真实素材缺失用标注占位，技术路径受阻交付最佳静态/轻量版本并继续其他页。

时间不够时，优先保证所有公开页面与主 3D 场景源资产完整；先削减重复装饰、额外镜头和非核心微交互。禁止只把首页精修到底而其余页面继续留成文字。

## 7. 最终交付与集中验收

继续扩展本目录，不再新增多套设计文档体系。最终至少包含：

1. 一个全站原型入口，逐页导航到全部公开页面、组件/动效演示和独立 M2 预案；链接中明确哪些是夹具、哪些是功能概念。
2. 公共样式与 token、可复用组件、字体方案、实际可操作脚本；必要依赖本地固定并提供启动命令，不强求 WebGL 原型双击 file URL 即可运行。
3. 3D 源资产/建模脚本、导出模型（如采用）、纹理、镜头/灯光参数、静态替代图、许可与依赖清单。另一位 AI 不依赖此模型的会话也能重建与调整。
4. 每类公开页面的桌面/手机与浅/深关键截图；主场景、页面切换、移动导航和主题切换录屏。记录浏览器/视口，模拟手机与真机明确区分。
5. 一份简短完成矩阵和最终交接：已完成、已实测、仅演示、缺口、生产规则调整建议、接入正式 Astro 的实施顺序。不要把原型验证记为生产验收。

集中检查：所有页可达、内容真实或夹具明确；真实 Markdown 能承载；动画可停止且不妨碍点击阅读；两主题可读；键盘/触控可操作；移动无整页意外横滚；字体/3D 失败有可读替代；资产可复现。性能报告注明测试条件，不把“约 1MB”“60fps”等估计写成测量。

设计评审以这套完整体验为对象，不回到逐个微交互先审批的循环。正式站点改动、规则修订、提交、推送与发布的范围，在原型交付后按用户指令执行。
