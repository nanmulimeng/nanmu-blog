## 1. 三个方向

### 方向 A「营造 · 本站施工图」(推荐)

把整个站点画成一座在施工的小院,用**轴测(等轴)投影的线稿 SVG** 呈现:正房住着手写文章(已建成,夜里亮灯);东厢是 AI 日报的工地(虚线线框+脚手架);南边一块留白画着将来的检索(虚线地界+界桩+小旗)。图面带指北针和图签(标题栏),图签里写真实日期与版次。

```
┌──────────────────────────────────────────────┐
│ [n] nanmu          首页 文章 日报 关于 [夜览] │
│──────────────────────────────────────────────│
│        北↑                                    │
│      ┌────正房(实线,亮窗)────┐  东厢(虚线)  │
│      │  本站施工图(轴测 SVG) │  留白(点线)  │
│      └───────图签:nanmu 制──┘               │
│ 先把最小的东西做完,上线,能用。  栏外注:本站是… │
│──────────────────────────────────────────────│
│ [文] 文章              1 篇 · 手写│ 栏外注     │
│  ─ 你好,nanmu-blog(摘要)       │ 订阅 RSS   │
│ [机] AI 日报           0 期      │ 关于       │
│  ┌图签式状态栏:尚未出第一期…┐   │            │
└──────────────────────────────────────────────┘
```

- **配色**(纸·墨·朱砂):纸本 `--paper #F4EEE0`、墨 `--ink #29241B`、次墨 `#6E6450`、界 `--line #D9CFB6`、朱砂 `--seal #B23A26`、灯 `--lamp #E9B45B`。**装饰与小字分色**(R2):印章/引线等装饰元素用 `--seal`,小字文本用更深的 `--seal-text`(昼 `#A5341F` ≈5.8:1,夜 `#DA6A55` ≈5.2:1),保证小字对比度 ≥4.5:1。
- **明暗关系**:不是反色,是"同一张图的两个时段"。夜览 `--paper #171916`(墨绿黑)、墨转月白 `#DDD5C2`、装饰朱砂微提亮 `#CE5340`;**正房窗灯在夜览时点亮并带辉光**——深色模式有自己的叙事,不是浅色版的照片负片。
- **字体**:思源宋体(Noto Serif SC)标题与正文;等宽(IBM Plex Mono)只管日期、编号、图签小字;引文用系统楷体。一个家族撑全场,靠字重 400/600/900 分层。
- **核心动效**:载入时线稿自绘一次(2.1s 内落定,末项=图签/指北针 1.5s 延迟 + 0.6s 渐入;见 §4 分镜);悬停房间沿轴测轴抬升;无持续动画。
- **为什么适合**:第一篇文章讲的就是"烂尾之后,把最小的东西盖完上线"——这个站的存在方式本身是一座在施工的小院。日报为空不是缺陷而是图纸上的虚线;"AI 生成必须标注"由图签和「机」印章天然承载。中文阅读温度(纸墨宋体)是三个方向里最好的。

### 方向 B「蓝晒 · 工程底图」

整站是一张带图框、折图标记的工程图纸。主视觉是**俯视总平面图**:实线房间=文章,虚线=日报,点线=检索;尺寸链标注的是真实数量("现存 1 篇"、"0 期")。文章列表即"图纸目录"表(编号/名称/日期/版次),日报条目带 AI 标签。

```
┌ 图框(带折图孔) ──────────────────────────┐
│ 图号 NM-SITE-001   NANMU-BLOG   总平面…  │
│ ┌──总平面 SVG──┐  ┌──图纸目录─────────┐ │
│ │ ▭文章 ▯日报  │  │ A-001 你好,… R0   │ │
│ │  ⟢检索  指北 │  │ B-…  日报系列[AI] │ │
│ │  尺寸链=真实数│  │ 制图说明(左竖条)  │ │
│ └──图签+修订戳─┘  └──────────────────┘ │
└──────────────────────────────────────────┘
```

- 配色:白纸 `#FBFBF7` + 制图墨蓝 `#1B3A6B`;深色=经典蓝晒底 `#0F2A55` + 青线 `#A9C8F0`(白纸与蓝晒互为正负片,双主题关系最巧)。
- 字体:黑体标题 + 大量等宽;正文黑体 16px/1.9。
- 动效:尺寸线载入时绘出;悬停房间斜线填充(hatch)渐显。
- **为什么适合 / 为什么不推荐**:与仓库的工程文化(spec/ADR/账本/证据)最同构,深色蓝晒辨识度极高。但它太冷——手写随笔是体温内容,蓝晒适合图纸不适合散文;且单色蓝在长文阅读上易疲劳。作为**备选**保留。

### 方向 C「活字 · 一色印刷」

编辑部式排印设计。主视觉是**活字盘**:6 列格盘里的字粒就是真实文章标题的用字(目前只有「你好,nanmu-blog」十三粒),其余钉位如实空着;悬停字粒翻面,露出铅字的反字凸面;点按进入该文章。竖排题记,目录式列表,全站一色墨。

```
│ 南木博客        目录 日报 关于 [夜印] │
│ 建│ 活 字 盘        现存字粒=已发布用字│
│ 站│ ┌─┬─┬─┬─┬─┬─┐                   │
│ 纪│ │你│好│,│n│a│n│  ← 悬停翻成铅字  │
│ ·│ ├─┼─┼─┼─┼─┼─┤                   │
│ 其│ │m│u│-│b│l│o│                   │
│ 一│ │g│░│░│░│░│░│  ← 空钉位如实空着  │
│  │ └─┴─┴─┴─┴─┴─┘                   │
│ 先把最小的东西做完(竖排)              │
│ 目 录                                │
│ 001 你好,nanmu-blog ……… 2026·10·02   │
│ [机印] 日报一辑:尚未开印              │
```

- 配色:宣纸 `#FCFBF5` + 墨 `#17150F` + 铅灰 `#B9B4A4`,一色印刷,无彩色;深色 `#141310` + `#E6E2D3`。
- 动效:字粒逐粒落盘(载入一次,错峰 0.65s);悬停翻面。
- **为什么适合 / 为什么不推荐**:对"写作"最诚实、字少时反而成立(空盘即事实)。但表达维度单一:日报的"机器"属性和站点的"渐进施工"叙事都要靠文字解释,主视觉撑不起整个信息架构;深色版只是黑纸,没有 A 的"夜览亮灯"那样的双主题关系。作为**备选**保留。

## 2. 推荐:A「营造」

决定性理由四条:

1. **主视觉即信息架构**:三个栏目(文章/日报/检索)的状态——已建成、施工中、图纸上——就是 spec 的原话("博客先上线,AI 是渐进叠加层")。读者在首屏直接读懂这个站。
2. **空状态是设计的一部分**:日报 0 期、文章 1 篇在图上是"虚线工地"和"一篇也亮灯",少内容不显得残缺。B 也做到这点,但 C 的目录在内容少时偏单薄。
3. **双主题有叙事**:夜览=掌灯,窗是画面唯一亮部。B 的正负片也巧,但偏概念;A 的明暗是读者能感到的。
4. **阅读质量最高**:长文页是宋体 17.5px、行距 2.05、行长 ≤34 字、两端对齐+标点悬挂、楷体引文、落款印——这是给中文长文写的规格,B/C 的正文都做不到这么妥帖。

## 3. 推荐方案页面规格

已建原型覆盖:**首页**(桌面 1440 / 手机 390,浅/深)、**文章详情页**(同四态)。要点:

- **首页**(R2 重构):导航(当前页常置墨线)→ **首屏双栏:左=作者定位+「最近在写」真实文章卡+日报状态条,右=施工图主视觉** → 双栏(文章列表 + 侧栏注记)→ AI 日报图签式状态栏 → 页脚。工程叙事退到印章/图签/栏外注,作者与内容先进首屏。手机端:导航折两行;首屏单列、内容在前图在后;图内小字标注隐藏,换成图下"图例"块;日报状态栏键值改上下排。
- **文章页**:印章面包屑(「文」章)→ 标题(比正文栏宽,书口式)→ mono 元信息行 → 正文 34em → 落款印「完」+ 日期行。排版基准样张(二级标题朱砂引条、楷体引文、代码块、插图+图注、分隔短线)已含在原型文末并标注为演示。
- **日报样张(R2 已建夹具原型)**:[direction-a-digest.html](prototypes/direction-a-digest.html),内容与站点无关、页顶有夹具横幅。覆盖:列表条目行式(「机」双线章区分);详情页图签固定落位 `ai_model`/`entry_count`/`cost_cny`;`cost_pending` false/true 两态对照("已核清" vs 朱砂"含未决,为保守上界");长标题两行折行;多条摘要+来源链接;手机端图签键值堆叠。附"小院状态对照":日报上线后东厢虚线变实线、窗亮起,同一座院子不用换图。
- **列表/归档页(规格)**:沿用首页列表行组件;分页器用"前一页/后一页"文字链,无页码堆叠。

## 4. 主视觉:本站施工图(轴测 SVG)

- **与博客的关系**:图即站。房间=栏目,线型=状态(实线已建成/虚线施工中/点线规划),窗灯=已发布内容,图签=版本与归属。它不会过时:日报上线那天,东厢从虚线变实线——主视觉随真实状态演进。
- **静止状态**:完整线稿+亮窗+引线标注+指北针+图签(见 shots/r2-a-home-desktop-light.png)。
- **交互**:悬停/聚焦房间 → 该体量沿轴测轴抬升 6px、对应引线加粗、聚焦时台基描边勾朱砂;点按 → 进对应栏目(`<a>` 包裹 `<g>`,键盘可达,R2 已用真实 Tab 走查验证)。触屏无悬停:图例文字常驻,点按直接跳转。
- **表现层两案(R2 对照稿 [hero-compare.html](prototypes/hero-compare.html))**:甲=现有线稿;乙=增强空间表现(落影、窗下光池、屋面瓦线、线重层级,纯 SVG/CSS,降级静默)。**推荐取乙案的"落影+光池+线重层级"三件套**——夜览叙事("院里亮着灯")明显更完整,增量只有 6 个 SVG 元素;瓦线在 390px 下糊成灰带,不进首版。
- **分镜**:见 [index.html](prototypes/index.html) 分镜表(0→5 镜,2.1s 内落定后完全静止;普通与 reduced-motion 完成态逐像素一致,R2 已复核)。
- **实现**:轴测投影是二维坐标变换,**纯内联 SVG + CSS,不经过 WebGL**。自绘 = `pathLength="1"` + `stroke-dashoffset` 动画;亮灯 = `fill-opacity` + `drop-shadow`;抬升 = `transform` 过渡。生产实现时 SVG 由构建期(或一次性脚本)生成后内联进 `.astro`,页面零脚本。

## 5. 动效实现与降级

| 动效 | 实现 | reduced-motion | 无 JS | 手机 |
|------|------|----------------|-------|------|
| 线稿自绘(载入一次) | CSS `stroke-dashoffset`,`pathLength=1` | 跳过,直接完成态 | 可用(纯 CSS) | 可用 |
| 房间抬升/引线加粗 | CSS `:hover`/`:focus-visible` + `transform` | 关闭位移,保留引线 | 可用 | 点按即跳转,不依赖悬停 |
| 夜览亮灯 | CSS 变量 + `drop-shadow` | 静态亮灯 | 可用 | 可用 |
| 导航墨线 / 列表朱砂点 / 链接下划线 | CSS 过渡 | 关闭 | 可用 | 可用 |
| 主题切换交叠 | CSS 变量 transition | 关闭过渡 | **缺席**(跟随系统) | 同左 |
| 字粒落盘(仅 C) | CSS keyframes 错峰 | 跳过 | 可用 | 可用 |

无 WebGL 需求;字体加载失败回退系统宋体/黑体,版式骨架不变。

## 6. 需要的规则调整(提案,未实施)

1. **手动主题切换需要唯一一段内联脚本**(读 `localStorage`/`prefers-color-scheme`,置 `data-theme`,防闪烁需在 `<head>` 同步执行)。这触碰 ADR-0002 的"零客户端 JS"。行为规格(R2 已定,原型可点):
   - **三态**:跟随系统(默认)/ 昼览 / 夜览,点击循环切换,按钮文案即当前态;
   - **持久化**:`localStorage['nm-theme']`,跨页一致;存储不可用(隐私模式等)时静默退化为跟随系统,不报错;
   - **首帧**:防闪烁要求脚本在 `<head>` 同步执行,在首绘前置好 `data-theme`;跟随系统态监听 `prefers-color-scheme` 变化实时跟随。
   - 两个选项:**方案一(建议)**ADR 增补"白名单单例外"——仅主题切换、内联、无依赖、构建期可审计;功能缺席时全站跟随系统,不损失内容与导航。**方案二(零改动)**不做手动切换,跟随系统,页脚注明。
   - 注意:"约 20 行"只是体量描述,不是验收标准;验收以行为为准(三态循环、跨页持久、存储异常静默、首帧无闪烁),原型中已逐条演示。
2. **字体自托管(R2 已定方案)**:采用**固定分片覆盖**——按 Google Fonts 官方 unicode-range 分片表(101 段)把整包 TTF 切成静态 woff2 分片,一次生成、与内容增长解耦:日报自动发布新增汉字自动命中既有分片,无需重新生成。可复现脚本已入库([tools/build-font-shards.py](tools/build-font-shards.py)),OFL 许可证文本随字体分发,来源/版本/RFN 注意点见 [FONTS.md](prototypes/fonts/FONTS.md)。实测(R2):分片 606 个文件、仓库体积约 18MB;**磁盘体积≠传输体积**——首页首载实际下载 28 个文件约 1MB,同站后续页面命中缓存。构建期脚本(fonttools)只在开发机运行,**运行时依赖白名单不变**;字体文件进 `site/public/fonts/` 静态资产。不同意时降级为系统字体栈,设计仍成立(原型早期截图即为系统字体效果)。
3. 不需要的调整:不引入 CSS 框架、不引入运行时依赖、不开客户端路由、不引入 WebGL(主视觉增强两案均为纯 SVG/CSS)。主视觉、动效、双主题全部在现行 CSS/SVG 能力内。

### 集中规则调整建议(一份提案,替代逐项审批)

现行 ADR-0002「零客户端 JS」需要一次性增补,建议表述为:**白名单三段脚本 + 一条 CSS 声明,全部渐进增强,缺席时内容/导航/主题均不损**。

1. **主题切换**(同 R2 §6.1,维持方案一):三态循环、localStorage 持久、`<head>` 同步防闪烁、存储异常静默。
2. **全站增强 `site.js`**(单文件、无依赖、可审计):移动菜单、IO reveal、阅读进度+目录高亮、代码复制、复制链接、lightbox。每一项独立缺席降级;reduced-motion 全局遵守;无 JS 时移动导航常显(`.js` 类门控)。
3. **首页 3D `boot.js` + `courtyard.js` + three r180 本地两文件(共 ~720KB,仅首页加载)**:WebGL 检测失败/模块失败 → poster;reduced-motion → 静态完成态;离屏暂停;移动端降载。M2 预案不进公开站。
4. **`@view-transition{navigation:auto}`**:纯 CSS 声明,不支持的浏览器静默跳过,无需规则改动,一并登记。

### 验证与缺测

实测(Chromium/Playwright):全页桌面昼、关键页桌面夜、移动 390(首页/导航开合/文章阅读)、reduced-motion(3D 静态完成态/404 静止)、无 JS(poster 降级/导航常显/内容全可读)、3D 拖拽/点击导航/复位、view-transition 中间帧、录屏四段(入场/页面切换/主题切换/移动导航,Chromium 模拟非真机)。证据在 `shots/r3-*` 与 `shots/rec/`。

本轮修到的真问题:文章页纯文本长 URL 在 390px 横向溢出(`.prose` 补 `overflow-wrap:anywhere`);无 JS 移动导航不可达(改为无 JS 常显、有 JS 才收起);poster 两张都拍成了夜景且带 HUD(重拍昼夜各一);R2 日报样张契约残留(去「已核清」「选自当日采集」,改真实三板块结构)。

缺测:真机(iOS/Android WebGL 与触控)、离屏暂停的电量收益、低 GPU 机型帧率、屏幕阅读器走查。原型验证不记为生产验收。
