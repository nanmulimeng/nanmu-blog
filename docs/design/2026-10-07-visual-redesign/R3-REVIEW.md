# R3 评审结论(2026-10-08,基于审计 AI 的只读评审,用户确认采纳)

> **结论:R3 保留为全站原型与交互骨架,但还不适合按最终视觉方案接入正式站点。**
> 下一轮主战场是**美术与动态表现的突破**,不是更多动画数量;页面、共享组件和程序化建模基础继续利用,不从头再做。
>
> 归属说明:本文"观察项/修复建议/转发稿"出自**审计 AI 的评审与建议**,经用户确认后作为下一轮执行依据;不是用户逐字指定的要求。

## 一、视觉判断(来自实际画面)

| 观察项 | R3 现状 | 下一轮方向 |
|---|---|---|
| 主视觉造型 | 墙体方块+巨大屋顶+单亮窗+低多边形树,接近建模初稿 | 独特轮廓、结构层次、细节重点;可保留小院,也可重新解释为书页建筑/现代书斋/知识装置 |
| 材质 | 屋顶/地面/墙体皆偏土黄,只靠颜色和明暗区分 | 可辨认的材质差异:纸、木、磨砂玻璃、金属边缘等,自主组合 |
| 夜景 | 屋顶和树黑成剪影,只剩窗户和地面光池 | 有方向的轮廓光+适量环境填光,夜间保留造型层次 |
| 页面与场景关系 | 3D 像嵌在右侧矩形框里的模型查看器 | 场景与标题、留白、导航共同构图:轮廓穿插、光影延伸、文字与空间对位 |
| 动态语言 | 入场/拖拽/悬停/主题切换/淡入,功能齐但无记忆点 | 一个鲜明的「招牌动作」:空间从字形展开、书页转版心、完整日夜照明变化等 |

- 参考转化目标:Lusion = 物体尺度/材质/遮挡形成的画面力量;Huly = 主光组织视线与信息层级。详见 [CREATIVE-REFERENCES.md](CREATIVE-REFERENCES.md)。
- **「619 个三角形」只证明场景轻,不证明设计完成。** 面数可继续很低,关键是每个形体、光源、材质都对画面有贡献。
- **「已定 A『营造』」不再理解为造型与配色不可更改**;最新指令允许重新解释甚至替换主视觉。

## 二、四项定点修复(下一轮同批做)

1. **日报样张与真实 Markdown 对齐**:样张给头条/精选标题加了链接、给分数和人工纳入加了专用 span 类;引擎实际输出标题是普通 `###` 文本,来源链接在列表项中(见 `engine/src/nanmu_engine/assemble.py` 与 `prototypes/site/digest-2026-10-05.html`)。**用真实格式的 Markdown 夹具渲染原型,再设计样式**;若确需徽章/标题链接,说明由哪一层生成并作为单独设计提案,不能靠手工 HTML 掩盖适配问题。
2. **lightbox 键盘焦点缺陷**(已复现):打开后焦点仍在原图按钮,Tab 会跳到被遮挡的背景链接。补齐:打开时焦点进入、背景真正不可交互、关闭后焦点返回、关闭事件清理。注意:**`aria-modal` 只是语义声明,不会自行阻止背景点击或键盘焦点移动**——应使用原生模态 `<dialog>`(`showModal()` 自带背景隔离与焦点约束),或手工实现 inert 背景 + 焦点圈定。不扩大成通用弹窗框架。见 `prototypes/site/assets/site.js`。
3. **reduced-motion 下主题与 3D 重绘缺口**(源码路径核对结论,未模拟复跑):`courtyard.js setTheme()` 只更新主题变量,没有连续渲染循环时不会重新应用材质灯光并绘制;且 boot.js 在建场景后才设初始主题,**「减少动态+初始深色」也需一起验证**。下一轮补两个明确场景:初始深色完成态、减少动态下的昼夜切换。
4. **持续环境动画缺暂停入口**:树/旗/夜灯持续变化,源码有 start/stop 但页面只有「复位视角」。增加轻量「暂停动态」控件,或让环境动效一段时间后自行停止;方式由设计模型选。

## 三、下一轮交付标准(审计建议,用户确认)

- 一张**暂停动画也成立**的首页完成态(构图、材质、字体、空间);
- 一套**两版都精心设计**的昼夜关系,夜间保留造型层次;
- 一个**能被记住**的动态片段(首屏入场/主题变化/进入文章 三选一重点突破,其余动效为它服务);
- **同一视觉语言覆盖全站**,不留「首页新作品、内页旧模板」的割裂;
- 真机/读屏/浏览器兼容只标缺测边界,**不占下一轮模型时间主体**;
- 不要把交付写成「增加了多少动画/对象/截图」。
