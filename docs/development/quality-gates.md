# 质量门禁(四级完成定义)

> 每一级都是硬门禁:不满足不进入下一级。来源:nanmuli-blog 死因之二"高标准劫持完成定义"的解毒剂——不是更高标准,而是**明确定义**。

## L1 · commit 级(每次提交)

- [ ] 对应层自动验证绿:site → `npm run verify`;engine → `python -m pytest -q`
- [ ] 无 secrets:diff 里不出现密码/API key/token(密钥只走环境变量)
- [ ] 改动与 commit message 一致;计划外改动已注明
- [ ] 行为变化已同步对应文档(运营三文档/README/AGENTS)

## L2 · 任务级(plan 的每个 Task)

- [ ] Task 的全部步骤 checkbox 勾选,验收步骤的输出符合 Expected
- [ ] 自动验证绿;人工验证项(视觉/浏览器)结果记入 session
- [ ] 不留"回头再补":TODO/占位/跳过的测试 = 任务未完成

## L3 · 里程碑级(spec §9 验收标准)

- [ ] 验收标准逐条**证据化**:curl 输出、测试统计、计时结果粘贴进 session 记录
- [ ] 回归检查:此前所有里程碑的验收项重跑一遍仍通过(已有站不死是铁律 2)
- [ ] 打 tag:`m0` / `m1` / `m2`(annotated),push tag
- [ ] 下一个里程碑的 plan 已写并经用户评审(**不欠债进下一个**,铁律 1)
- [ ] docs/README.md 的状态列更新

## L4 · 部署级(每次上服务器)

- [ ] 按 runbook 逐字执行,关键输出留痕进 session
- [ ] 线上冒烟:首页 200、RSS 可取、关键路径抽查(部署韧性的自动保障:`mv -T` 原子切换 + 构建失败不切 symlink,ADR-0007)
- [ ] 新增/变更的服务器事实回填 `docs/context/server-environment.md`([declared] 项核实后摘帽)
- [ ] 涉及 engine 时:当日成本入 `docs/engine/budget.md` 台账

## 未来计划的强制测试清单

写 M1/M2 plan 时,以下测试**必须**出现在对应任务里(来自 spec 风险清单,缺一不可):

| # | 测试 | 钉住的风险 |
|---|------|------------|
| 1 | URL 归一边界用例(追踪参数/微信四参/www/大小写) | 判重失效 → 重复条目 |
| 2 | 评分和判边界(两次分数跨门槛的组合) | 入选判据实现错误 |
| 3 | 回执状态机全迁移 + 崩溃恢复复用 | 重复扣费/丢失已付费结果 |
| 4 | 三级预算窗口计数 + 熔断注入(预算调 0 立即停) | 成本失控(铁律 5) |
| 5 | frontmatter 契约(生成的 markdown 能过 Astro schema) | 坏文件阻塞整站构建 |
| 6 | topic-digest schema 依赖(模拟上游改字段名 → 测试红) | 上游演进静默破坏 collect |
| 7 | digest 空态与单条失败不挂整期 | 失败隔离不变量 |
| 8 | (M2)embedding 失败降级 FTS;换模型触发全量重建 | 检索单点故障;陈旧向量 |
| 9 | (M2)`/ask` 无来源拒答 | 幻觉答案无法核验 |

## 红线(任何时候)

- 已上线里程碑的任何验收项被后续开发破坏 = **阻塞一切发布**,先修复再继续
- 跳过门禁"先上线再说" = 不允许;这个项目的历史就是死在这上面
