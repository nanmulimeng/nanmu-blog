# 质量门禁(按活动适用)

> L1-L4是检查分类,不是必须依次通过的阶梯。提交适用L1,任务适用L2,里程碑适用L3,每次部署适用L4;M0先通过部署验证,再汇总里程碑验收。来源:nanmuli-blog 死因之二"高标准劫持完成定义"的解毒剂——不是更高标准,而是**明确定义**。

## 验证矩阵与证据口径

只选择当前改动涉及的行。表中目录/命令须已存在;未来阶段不提前执行,缺环境不等于通过。纯文档修改也必须核对其描述与实际文件,不能只依赖脚本。

| 改动范围 | 工作目录与自动检查 | 补充验收及边界 |
|----------|--------------------|----------------|
| 文档、Agent规则、交接模板 | 仓库根:`python scripts/check_docs.py`、`git diff --check` | 人工核对授权、状态、真相源和阅读路径;链接通过不证明叙述正确 |
| M0计划中的脚本/JS/JSON片段 | 仓库根:上述检查加 `python scripts/check_docs.py --snippets` | 需要Node/Git Bash;Windows显式Bash路径见[文档索引](../README.md)。语法/夹具通过不代表Astro构建或部署成功 |
| site,Task2-6 | `site/`:`npm run build` | 按当前Task检查产物;涉及页面时本地浏览器核对对应路由、布局与主题 |
| site,Task7起 | `site/`:`npm run verify` | 已包含build,无相关变化不重复跑build;视觉检查仍须实际打开页面 |
| 可运行的engine | `engine/`:`python -m pytest -q` | 单测mock付费与外部IO;真实日报仅在已授权的部署/里程碑验收中运行,调用前核对实时预算 |
| 部署/服务器变更 | 按[部署手册](../ops/deploy.md)指定的本地/服务器目录执行 | 对应工件检查、HTTP/日志/线上SHA及浏览器验收;本地测试不能替代L4 |

- 证据至少含工作目录、实际命令/操作、退出码或状态、关键输出摘要。后台进程须取得完成结果;手动检查记录页面和结果,不能只写“已检查”。
- 区分“通过”“失败”“未运行”“不适用”。失败记录原因与影响;未运行说明缺什么,不得用预期输出或以前会话的结果冒充本轮实测。
- 检查通过后相关文件又有修改,重跑受影响检查;仅改无关记录不机械重跑所有测试。
- 新增测试应覆盖实际风险,不要求文案修改、可逆低影响调整编写复述实现的测试。完整M1/M2清单仅在对应计划实施时适用。

2026-10-04审查已复现两项边界:当前路径检查只看Astro生成的id,可被frontmatter `slug`绕过;Astro5.18.2删除最后一篇digest后,持久data-store可能继续产出旧内容。**修复和自动回归归M0 Task8a,目前不能用verify绿证明这两项已通过。**

- 删除、改名、撤回内容或清理临时fixture后,停止dev进程;核对仓库根与解析后的缓存目录仅为本站的`site/.astro/`和`site/node_modules/.astro/`,确认未通过符号链接/junction指向外部后仅清理这两个可再生目录。不要删除整个node_modules、源内容或其他工作区。

- Task8a必须另做**有缓存的两次连续构建**:先构建唯一公开fixture,再删除它并运行修订后的正式验证入口;不靠测试提前手动清缓存掩盖实现问题。覆盖posts与digest,并分别验证改名、draft撤回和fixture清理后无残留;负例只在独立临时副本中执行。
- 生产deploy按SHA创建全新archive工作目录,当前风险主要在本地开发与M1持久工作副本。Task8a完成后将清理/失效处理纳入正式构建入口或loader,并更新本节的待实现说明;不得只在交接中口头要求每次手工补救。

## L1 · commit 级(每次提交)

- [ ] 上表中当前阶段与改动范围对应的验证通过,没有把环境缺失记作成功
- [ ] 无 secrets:diff 里不出现密码/API key/token(密钥只走环境变量)
- [ ] 已获提交授权;暂存区内容与 commit message 一致,不混入未确认的已有改动;计划外必要修正已注明
- [ ] 行为变化已同步对应文档(运营三文档/README/AGENTS)

## L2 · 任务级(plan 的每个 Task)

- [ ] Task 的全部必需步骤实际完成后勾选,验收步骤的输出符合 Expected;文档示例或测试替身不算生产步骤完成
- [ ] 自动验证绿;人工验证项(视觉/浏览器)结果记入 session
- [ ] 当前任务承诺范围内不留TODO/占位/跳过的必需测试;明确排入后续里程碑的设计项不阻塞本任务

- [ ] 验收标准逐条**证据化**:curl 输出、测试统计、计时结果粘贴进 session 记录
- [ ] 回归检查:覆盖本次影响路径与已有站点核心冒烟;M2不机械重跑M1首次上线连续3天验收,但须验证已发布博客、日报读取和预算隔离未被破坏
- [ ] 在里程碑发布授权覆盖范围内打 tag:`m0` / `m1` / `m2`(annotated),核对remote后push tag;未授权则记录待发布,不声称发布完成
- [ ] 本里程碑范围内无阻塞缺口;下一阶段 plan 待启动时编写并经用户评审,这是进入下一阶段的门槛,不阻塞当前里程碑独立完成
- [ ] docs/README.md 的状态列更新

## L4 · 部署级(每次上服务器)

- [ ] 先核对现场与部署手册一致再执行;不符先修正文档,关键输出留痕进 session
- [ ] 线上冒烟:首页 200、RSS 可取、关键路径/真实404/Caddy读取权限/线上SHA抽查(部署韧性要求:`mv -T` 原子切换 + 构建失败不切 symlink,ADR-0007)
- [ ] 新增/变更的服务器事实回填 `docs/context/server-environment.md`([declared] 项核实后摘帽)
- [ ] 涉及engine付费时:费用即时入账本,月度汇总回填budget.md;文档台账不替代实时记账

## 未来计划的强制测试清单

写 M1/M2 plan 时,以下测试**必须**出现在对应任务里(来自 spec 风险清单,缺一不可):

| # | 测试 | 钉住的风险 |
|---|------|------------|
| 1 | URL归一边界与固定输入输出(追踪参数/微信四参/www/大小写/原始默认端口/根与带query尾斜杠/重复参数) | 判重失效 → 重复条目 |
| 2 | 评分和判边界(两次分数跨门槛的组合) | 入选判据实现错误 |
| 3 | 回执状态机全迁移、崩溃恢复复用、普通/unknown共享总上限;MockTransport断言原始HTTP顶层thinking/json_object及finish_reason处理 | 重复扣费/丢失已付费结果/错误请求契约 |
| 4 | 按尝试时间的三级窗口、月/期整数金额预占、百万token单位换算、摘要与重试预留、跨月unknown、运行中调0停增但可复用、非法/缺配置拒绝调用 | 成本失控(铁律5);固定算例见engine/design |
| 5 | frontmatter 契约(生成的 markdown 能过 Astro schema) | 坏文件阻塞整站构建 |
| 6 | 上游schema/JOIN依赖、fresh/clustered均读取、dropped排除、正文空值、只读WAL权限 | 上游演进静默破坏 collect |
| 7 | digest 空态与单条失败不挂整期 | 失败隔离不变量 |
| 8 | (M2)embedding 失败降级 FTS;换模型触发全量重建 | 检索单点故障;陈旧向量 |
| 9 | (M2)中文短词/混合语检索、无证据拒答、来源真在检索集、draft与删改索引、付费预算并发 | 幻觉答案无法核验 |
| 10 | 发布 push冲突/超时/重复运行与费用复用;已提交不等于已上线 | 发布状态误报/重复付费 |

第3/4/10项按engine/design错误矩阵、budget与pipeline的恢复表展开:遗留pending、unknown等待与重试上限、429/500/503退避、400/401/422不自动重试、402即时通知、HTTP 200但非法JSON/截断、无产物failed、commit/push/上线成功后未写状态、撤回防重发、费用快照含失败尝试,均须有可重复的故障用例。所有付费边界先用替身验证;固定算例、字段范围与错误处置引用真相源,不在计划中另定义一套。

M0 Task 9 的坏构建注入只在独立验收目标执行;生产 main 不允许通过“测试需要”绕过 L1。

## 红线(任何时候)

- 故障阻塞受影响功能的新发布。AI/问答故障不得阻止独立且验证通过的个人文章、静态站修复或回滚;破坏博客构建/公开内容契约的变更必须先修复,不能借隔离原则绕过本站验证
- 跳过适用门禁不允许;门禁也不得持续扩张成无法交付的标准,新增条件须对应已确认风险
