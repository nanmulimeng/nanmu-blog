## 0. 评审目标(本文通过的标准)

拿到一份输入材料和一个运行场景,只读本文及引用的契约,就能明确判断:**应该产生什么内容、留下什么状态、失败后如何继续、每个状态下允许哪些人工操作**——以 §4.2 状态×操作矩阵为准,不需要读者自行发明或在互相冲突的规则间选择。

## 2. 内容字段与状态约定(两层样例的衔接契约)

功能与内容样例和页面呈现样例通过本表衔接:字段与状态先定死,页面只决定"怎么摆",不能引入本表之外的信息需求(要引入=先评审数据影响,见 §6)。

**期级(frontmatter,site 构建契约,spec §4.1 schema)**:

| 字段 | 类型 | 规则 |
|------|------|------|
| date | YYYY-MM-DD | 与文件名一致;运行开始时按 Asia/Shanghai 确定 |
| generated | true | 恒真 |
| ai_model | string | 本期实际调用模型;一期一模型(selection M1确定性边界) |
| entry_count | int | 正文条目数,修订后如实更新 |
| cost_cny | number | 发布时费用快照:该期全部 attempt 实付+未决保守预占,不重复计(pipeline 公开成本口径) |
| cost_pending | boolean,缺省 false | **决策(v2 提出,v2 评审接受)**:该期存在未决预占时为 true;列表条目与详情页头的成本数字追加"(含未决预占)",正文标注行同步——三处口径一致,满足 budget"统一文案或扩展明确字段"的字段路线。三约束:①`cost_cny` 与 `cost_pending` 出自**同一时点、同一期费用快照**,不得分别查询形成不同口径;②未决判定覆盖**所有尚未核清费用的 attempt**(不限于 `status=unknown`,含已收响应未结算等 `actual` 未核清情形);③新生成日报**显式写出布尔值**,`default(false)` 仅为旧文件兼容;核清时数字、标志与正文标注一起更新。schema 扩为已定义可选键,实施同步 spec/pipeline/schema 说明在功能评审通过后随第 3 步进行,site 代码改动仍待实施许可 |

**条目级**:

| 字段 | 归属 | 规则 |
|------|------|------|
| 中文标题 / 一句话摘要 / 推荐理由 | 读者可见 | understand 输出契约:标题≤30字答案先行、摘要一句话、理由不含来源未提的实体 |
| 原文链接 / 源名 / 展示分 / 板块 | 读者可见 | 链接必带;展示分=floor((score_1+score_2)/2);板块按展示分与源 tier 落位;人工纳入条目加标注(§5.2) |
| identity_key / url / published_utc / discovered_utc / source_tier | 系统内部 | spec §5.3 entry 表;判重键规则见 design.md |
| score_1 / score_2 / receipt 关联 | 系统内部 | analysis 表;跨期复用规则见 §4.6 |
| tags(≤3) | 系统内部 | **决策(v2 修正)**:understand 产出,M1 不写入公开 Markdown、不展示(延期决策,非技术约束——`.strict()` 只限制 frontmatter 未知键,不禁止正文文字;未来展示走正文标签行,无需 schema 变更)。engine 侧存储仅用于排查;M2 语料真相源是已发布 Markdown、不依赖 tags,v1 的"服务 M2 语料"说法撤回 |

**期状态与叠加标志(引擎内部)**:

- 期状态沿用四值:无期记录(生成中)→ draft → submitted → published。
- **failed 是生成路径上的失败终态**(collect 失败、零候选、零合格、LLM 全挂),此时无产物或产物未进发布流程。**发布窗口失败(E8 冲突/E9 超时)不落 failed**——保留 draft/submitted 转人工,与 pipeline 恢复表一致(修正 v1"任一阶段的失败终态"表述)。
- **暂停标志与撤回事实是叠加标志,不是新状态值**(决策,沿 v1):暂停可叠加在任何状态上,语义=调度跳过该期一切自动动作;撤回记录在 published 之上(发布是历史事实,当前可见性由站点内容决定),不引入 withdrawn 值。
- 存储映射(标志放哪张表、期行何时建行)不预设,见 §7。

```markdown
## 精选(75-79)

### 开源数据库 NanoDB 发布 3.0,查询计划器全部重写

- 3.0 把查询计划器换成代价模型驱动,官方基准称复杂连接快 2.4 倍。
- 可复用的工程方法:重写计划器的迁移策略与回归基准值得细读。[来源](https://example.com/nanodb-3)(TechCrunch · 展示分 77)

## 值得一瞥(压线入选)

- [国内团队开源长上下文注意力变体,128K 下显存占用减半](https://example.com/attn-var)(量子位 · 展示分 71)——训练配置与推理代码同时放出,可复现。

```

核验点(对照规则):板块归属——86≥80 入头条;77∈[75,79] 入精选(T2 过线);71 为 T1 源∈[60,74] 入一瞥;20 未过 T2 门槛 75,因 override force_include 人工纳入,固定「值得一瞥」末尾并标注(§5.2)。排序——各板块内展示分降序,强制项恒末尾。字段——每条有链接/源名/展示分;frontmatter 六字段齐;`cost_pending` 缺省即 false。成本构成(虚构):12 条候选×2 评分+4 摘要+1 次失败重试,29 次 attempt 全部结算,合计 ¥0.11。

### 3.2 变体 A:少量条目(仅 2 条,均一瞥)

frontmatter `entry_count: 2`、`cost_cny: 0.07`;正文只有「值得一瞥」一个板块(头条/精选标题不输出,不生成空标题凑结构),两条按展示分降序。

### 3.3 变体 B:无头条

有精选与一瞥、无头条:省略头条板块标题,其余照常;页面不解释"为什么没有头条"。

### 3.4 变体 C:含未决费用

同基准样例,另有 1 次 unknown 保守预占 ¥0.01:`cost_cny: 0.12`、`cost_pending: true`;正文标注行为:

```markdown
> AI 生成与精选 · 模型 deepseek-flash · 成本 ¥0.12(含未决预占,为保守上界)
```

同一期列表条目与详情页头显示"成本 ¥0.12(含未决预占)"——三处同源同口径(§2);不得把含未决数字标成实付或写 0。后续核清纠正走正常内容提交(更新数字与标志),不另发模型请求(pipeline 公开成本口径)。

### 3.5 零合格条目(该期不发布)

**不生成任何 markdown、不建 draft**——不为凑样例生成空日报。落库:期记 failed(`entry_ids='[]'`、无 markdown 路径)。旧站保留:昨天的日报仍列表可见,今日无新期。维护者侧:退出码 3;通知按 E6"连续 2 期去重"规则——**本期为该错误子类连续第一期失败时静默,次期仍失败才告警**(修正 v1"立即收到通知"暗示);status 命令输出样例(格式样例,字段顺序实现时可调):

```text
$ python -m nanmu_engine.status --issue 2026-10-07
issue 2026-10-07  status=failed  reason=E6.llm_all_failed
entries: 0 selected / 0 scored / 34 frozen candidates
attempts: 62 settled ¥0.58 / 1 unknown ¥0.01 reserved
last_run end=2026-10-07T00:41:05Z exit=3
next: 人工显式重跑(候选已冻结、已收响应复用,不重复付费);不自动重试
```

零候选(冻结结果为空集合)同样落 failed(reason=no_candidates),零付费;通知按"无合格产物"既有去重口径。

### 3.6 撤回后的表现

撤回 2026-10-06 期之后:`/digest/2026-10-06/` 返回 404;`/digest/` 列表与 `/digest.xml` 不再包含该期(删除文件后按质量门禁验证列表/详情/RSS 三处,Task8a 缓存契约);引擎侧 status 显示 `status=published  withdrawn=yes(撤回提交 <sha>)`。重新上线≠重新生成:走 §4.5"恢复经确认的内容版本"。

### 3.7 边界场景(文字,不堆虚构内容)

- **满量 15 条**:候选截断排序(T1 优先→discovered_utc 降序→identity_key 升序)在预筛执行;展示时各板块内按展示分降序、同分按可用 published_utc 降序、再按 identity_key 升序(selection M1确定性边界)。结构同基准样例,不设第 16 条。
- **强制项数量计算(决策,v3)**:先保留全部有效强制项,记数 F;**F>15 → 组装暂停+转人工要求缩减**(selection"有效强制项超上限"按此理解);**F≤15 → 普通合格项按既定排序最多取 15−F 条**。反例裁定:15 条普通合格+1 条强制项 = 1 强制+排序最高的 14 条普通,正常发布,不暂停。展示时强制项仍按 §5.2 规则置于「值得一瞥」末尾。强制项自身无法完成评分、摘要或安全校验时,暂停转人工的规则不变(§5.2)。
- **同分平局**:同板块同展示分按上述平局依据,样例不另造。

## 4. 一期生命周期

### 4.1 期状态机

```text
(无期记录)──collect 完成,冻结确认──▶(生成中,已冻结)
    │                                   │评分/摘要,写 entry/analysis/receipt
    │ collect 失败                        ▼
    └──▶ failed(生成路径失败终态,      组装出产物 ──▶ draft ──push──▶ submitted ──线上确认──▶ published
         含零候选/零合格/LLM全挂)                        │                        │
                                                    push 冲突/超时            push 冲突/超时
                                                    (保留 draft,转人工)      (保留 submitted,只重查)
```

发布窗口失败不落 failed(§2);期行创建时机属存储映射,不在本文预定(§7)。

### 4.2 状态×操作矩阵(统一裁决表,冲突时以本表为准)

| 期状态 | 调度自动推进 | 人工显式重跑 | 重新组装(删旧产物重走组装) | 纠错提交 | 撤回 | 重新上线 |
|--------|--------------|--------------|------------------------------|----------|------|----------|
| 生成中(冻结已确认) | 是;自动推进上限见 §4.6 | 是(=立即续跑) | —(尚无产物) | — | — | — |
| draft | 是;同上 | 是 | **是**,前提=核对工作副本无该期未推送提交且远端无该期内容 | —(未发布,改内容走重新组装) | —(未发布无需撤回) | — |
| submitted | 只读线上确认:是;写操作:否 | 先核清远端/线上状态,按 pipeline 恢复表推进 | **否**(远端已接收,重组装=两份内容竞争同一期发布身份) | 核清后:已实际上线→按 published 纠错;未上线→先走发布恢复 | 核清后:已上线→按 published 撤回 | — |
| published | —(终态) | — | 否 | **是**(新的已校验提交) | **是**(§5.6) | — |
| published+已撤回 | — | — | 否 | **允许离线纠错**(在离线工作副本修正历史内容,验证后以待发布状态保存);纠错完成后经**显式重新上线**操作发布,期间保持撤回状态 | —(已撤回) | **是**,两条(§4.5):原样恢复 / 修正后恢复 |
| failed | **否**(不自动重跑) | **是**(续跑语义:候选冻结、回执复用) | 并入人工重跑(重组装是其子步骤) | — | — | — |

**暂停标志**(可叠加任意状态):调度跳过该期一切自动动作;**解除暂停只恢复"可被调度处理",不改变期状态、不撤销撤回、不触发任何发布**(决策,修正 v1 §5.4/§5.6 与 §4.4 的冲突)。

### 4.3 阶段表(在 pipeline 阶段表之上补状态与冻结语义)

| 阶段 | 输入 | 输出与状态变化 | 失败去向 |
|------|------|----------------|----------|
| 0 定期 | 调度触发时刻 | issue_date=当时 Asia/Shanghai 日期(**补跑按补跑时刻定期,不回补停机各日**) | — |
| 1 collect | 上游只读,fetched_utc 近 48h | 候选与输入版本快照写入;结束时写**冻结确认**(§4.4),允许空集合 | E2 → failed(未冻结可重收集);冻结确认未写入=冻结未发生 |
| 2 预筛 | 冻结候选 | 剔除黑名单/死源/空正文/已 used/override exclude;按预算截断(公式见 design.md) | 本地零成本,无期级失败 |
| 3 双次评分 | 入围条目 | analysis(score_1/score_2);entry→scored;入选→selected(按当期判据,§4.6) | 额度停→带已有合格条目前进;单条失败跳过(强制项例外→§5.2) |
| 4 摘要 | 入选条目 | 摘要 JSON | 单条失败剔除该条,不挂期(强制项例外→§5.2) |
| 5 组装 | 入选+摘要 | digest markdown 落工作副本;期=draft;零合格/零候选→failed(§3.5) | — |
| 6 发布 | 已验证产物 | push→submitted;线上确认→published;**entry→used 仅在确认 published 后** | E8/E9 → 保留原状态转人工(§2) |
| 7 汇总 | 全部 attempt | api_usage 投影、期成本快照 | 失败期同样记账 |

### 4.4 候选窗口冻结(功能契约;存储映射见 §7)

- **冻结是一次可持久化确认的事件**,在 collect 阶段结束时写入:内容=候选成员(identity_key 集合,允许为空)+每成员本期使用的输入版本(正文快照及其 hash)。冻结成功前进程退出=**半成品,不算冻结**。
- 冻结后该期一切续跑只使用冻结内容,**不重新 collect、不悄悄替换正文**;上游之后的新抓取与新版本不进入本期。
- 判定规则(功能层):该期**有冻结确认标志**→按冻结续跑;**无标志且零回执**→冻结未发生,重跑从头 collect(窗口=重跑时刻,已写入的 entry 行幂等);**无标志但有回执**→不可能(评分只在冻结确认后开始),按数据异常排查处理。
- 允许**冻结空集合**:0 候选是合法采集结果→期 failed(reason=no_candidates),零付费(§3.5)。
- 理由:冻结把"一次生成"变成对固定输入的可重放计算——续跑重放不改变候选与正文,回执复用与费用一致性才成立。物理存储(确认标志与清单放哪、期行何时建行)**不预设**,第 3 步只须满足:冻结事实可查证、生成中可恢复、不伪造可发布 draft。

### 4.5 运行种类:续跑 / 补跑 / 重新组装 / 重新上线(术语定稿,v2 收窄)

| 术语 | 语义 | 允许范围(以 §4.2 矩阵为准) | 费用 | 候选集 |
|------|------|------------------------------|------|--------|
| **续跑(恢复)** | 同 issue_date 从库内状态继续:复用已收响应(按完整请求身份)、继续未完成阶段 | 生成中/draft/submitted 的调度自动推进(§4.6 上限)与人工重跑;failed 期人工显式重跑 | 已付不重付 | 已冻结,不扩员 |
| **补跑** | 调度错过后的一次运行(systemd Persistent):按补跑时刻日期定期——该日无期数据=全新生成;已有未完成期=续跑。**停机多天只补一期,不回补每一天** | 同上 | 同上 | 新期按补跑时刻窗口 |
| **重新组装** | 删旧产物、清该期组装结果、重走组装 | **仅 draft 且核对无远端接收记录**(工作副本无该期未推送提交、远端无该期内容);submitted/published/已撤回一律不允许 | 复用照旧,新请求身份才新付费 | 已冻结,不扩员 |
| **重新上线** | 两条,均不重新调模型、不重新组装,显式命令+留痕:**原样恢复**=把撤回时经确认可再次公开的历史内容(git 历史中该期产物)重新提交上线;**修正后恢复**=在离线工作副本修正历史内容,本地 verify 后以一次新提交重新上线(不先恢复错误版本) | **仅已撤回的 published**(§4.2 矩阵);解除暂停不触发重新上线 | 零模型费用;修正中如需重写摘要=新请求身份、新费用 |

已发布期(含已撤回)的内容变更一律走纠错式新提交(§5.5);"撤回后解除暂停即可重发"的 v1 表述作废(§4.2 暂停行)。

### 4.6 跨期:旧期与新期、复用与占用(决策)

- **"旧期不阻塞新期"限定为内容级**:旧期的 collect/评分/摘要失败不阻止新期采集与生成。**共用发布链(Git 工作副本)或账本异常时,受影响的发布/付费操作允许暂停**——新期可继续生成产物但暂不 push。
- **新期 push 前必须核对工作副本无待人工处理的旧期未推送提交**;有→不 push、转人工。一次 push 不得意外带出待人工的旧期内容。
- **自动恢复上限**:每个未完成期(生成中/draft/submitted)的自动推进尝试上限 **1 个后续调度日**(只读线上确认不受限);到限仍非终态→通知+转人工。不让旧期恢复耗尽运行窗口、不让新期一直等。
- **failed 不自动重跑**:调度自动处理对象仅为生成中/draft/submitted 的推进;failed 一律人工显式重跑(§3.5 样例 next 行)。放弃失败期=人工核对后释放其占用条目(selected 回可评估状态,已 used 不动,留痕)。
- **快照更新与冻结的边界(v3 修正,对齐 [data-source](../context/topic-digest-data-source.md) "M1读取与快照补充")**:**期冻结约束本期,不约束 entry 的后续更新**。entry 可以接收上游再次读取到的刷新(未发布条目正文由空变非空或内容变更时允许刷新快照,请求 hash 随内容变化,旧付费回执保留但不得冒充新内容的结果;已发布条目不自动重新评分/发布)——这利用正常 collect 时的再读取,不增加主动抓取、更新监听或版本平台。**每一期一旦冻结,其成员与输入版本不再改变**:新一期可采用较新的输入版本,旧期续跑仍使用旧期冻结时的快照。
- **响应复用与入选判断分离**(修正 v1):
  - *模型响应是否可复用*——只由**完整请求身份**决定(budget 契约:provider/endpoint/purpose/model/request_hash/attemptTag;request_hash 覆盖实际输入内容、prompt 版本、模型与参数等全部要素)。正文快照刷新后输入变化,请求身份即变化,旧响应不得复用于新输入——不存在"prompt 与模型不变则身份不变"的简化推论。
  - *本期是否入选*——不跨期继承。每期按**当期**门槛、人工覆盖、条目占用重新判断;上期落选(如因正文为空被预筛排除)本期补齐正文后可再入围并重新评分。
- **条目占用**:未发布期选中的条目不被其他待发布期占用(pipeline 既有);**未入选条目的自然淘汰**:rejected 条目次日仍可再入围;discovered_utc 滑出 48h 窗口即不再成为候选。M1 不设落选冷却期。

## 5. 人工维护流程(六场景)

统一约束:所有操作有命令或 Git 证据并留痕;已发生费用一律不退不改(账本是事实记录);对已发布内容的任何修改都走"新的已校验提交",不重写历史;**override 与人工操作在阶段边界生效**——单次进程运行中段的修改不保证即时生效,需立即生效先暂停该期(决策)。

| # | 场景 | 触发与操作 | 生效范围与时机 | 费用 | 文件 | 已发布内容 |
|---|------|------------|----------------|------|------|------------|
| 5.1 | 排除条目 | override 写 `(identity_key, exclude, reason)` | 该 URL 的所有后续评估;下一次阶段边界起生效。对进行中的期:生成中/draft→组装边界移除该条并重新组装(其余摘要复用,零新增费用);**submitted→不动本地文件**,先核清旧产物发布状态(已上线→按纠错/撤回;未上线→先走发布恢复);published→不追溯 | 已付不退 | 仅未发布期重组装 | 走 5.5/5.6 |
| 5.2 | 强制纳入 | override 写 `(identity_key, force_include, reason)`;条目须在冻结候选集中且有可核验正文 | 同上边界生效;当期+后续的每次评估,可删除恢复纯评分判据 | 正常计费:强制项仍执行双次评分与摘要 | 参与组装,落位见下 | 同 5.1 |
| 5.3 | 暂停一期 | 置期级暂停标志(命令,带原因) | 仅该期:调度跳过一切自动动作(W1);其他期与新期照常 | 无 | 冻结现状 | 冻结现状 |
| 5.4 | 解除暂停 | 显式解除(留痕) | **只恢复该期可被调度处理**;不改变状态、不撤销撤回、不触发发布;此后按 §4.2 矩阵与续跑语义推进 | 复用照旧 | 按 §4.2 | 不变 |
| 5.5 | 纠错 | 专用工作副本修订该期 markdown → 本地 verify → commit+push → 线上确认;引擎补记纠错提交 | 仅 published(矩阵);条目级错误同时写 5.1 防再犯 | 修订零模型费用;重写摘要=新请求身份、新费用归该期 | 该期文件更新,entry_count 如实变化 | 新版本替换旧版本,历史提交保留 |
| 5.6 | 撤回整期 | ①置暂停标志(防自动重发)②删该期文件 → verify → push → 确认列表/详情/RSS 三处消失③引擎记录撤回事实(status 保持 published+撤回提交) | 整期下线;重新上线两条(§4.5):**原样恢复 / 修正后恢复**——发现撤回内容有错时可直接修正后恢复,不必先重新公开错误版本 | 不退不改 | 文件删除(404,无占位页) | 从站点消失 |

**强制项纪律(v2 补齐)**:

- **落位(决策)**:强制项无论展示分高低,固定归「值得一瞥」板块**末尾**,条目标注"(人工纳入)"——板块是编辑判断的表达,人工意志不伪装成模型高分,读者知情(样例见 §3.1 第 4 条,展示分 20)。M1 不提供板块指定。
- **失败处理统一**:阻止强制项发布的任何原因——强制项自身超上限(F>15,§3.7)、评分未完成(预算停)、评分解析失败/重试耗尽、摘要失败——同一处理:**组装暂停+转人工通知**。这是"单条目失败不挂期"不变量对强制项的显式例外(人工意志不静默丢弃、不静默降级)。
- 强制项只越过评分门槛,不绕过来源/输入安全/预算约束(selection 既有)。
